# 코드 크래프터: 조성 왕국 복원기
## 조성별 다이아토닉 코드 구성 원리를 배우는 2D 모바일 게임 웹앱 시나리오 + 바이브코딩 프롬프트

> 문서 목적  
> 이 문서는 **기획자·디자이너·개발자가 바로 구현을 시작할 수 있는 수준**으로 게임의 학습 목표, 세계관, 스테이지 구조, 상호작용, 음악이론 규칙, 데이터 구조, 개발 순서, 테스트 기준을 정의한다.  
> 마지막의 **“통합 바이브코딩 프롬프트”**는 그대로 복사해 코딩 에이전트에 입력할 수 있다.

---

## 0. 한눈에 보는 프로젝트

- **가제:** 코드 크래프터: 조성 왕국 복원기
- **장르:** 2D 퍼즐·수집·학습 RPG
- **플랫폼:** 모바일 우선 웹앱, 세로 화면, PWA 확장 가능
- **핵심 학습 주제:** 각 장조·단조에서 음계를 만들고, 음계의 각 음 위에 3도를 두 번 쌓아 다이아토닉 3화음을 구성하는 원리
- **주요 대상:** 음악이론 입문자, 작곡 입문자, 악기 학습자, 중·고등학생 및 성인
- **1회 플레이 길이:** 2~5분
- **핵심 플레이 감정:** “외운 답을 맞혔다”가 아니라 “내가 직접 음을 쌓아서 원리를 발견했다”
- **MVP 범위:** C 장조·A 단조, 핵심 6개 스테이지, 자유 연습, 로컬 저장, 합성음 재생
- **정식 핵심 범위:** 12개 음고 중심의 장조 12개 + 자연단조 12개, 12개 상대조 지역, 데이터 기반 156개 스테이지 생성, 복습·도감·도전 모드
- **고급 표기 확장:** 이명동음 거울 지역 3개를 더해 관습적으로 쓰는 **15개 장조 + 15개 단조 표기**를 모두 학습, 확장 시 총 195개 스테이지

### 핵심 한 문장

> 플레이어는 조성 왕국을 이동하며 **음계 조각을 수집하고, 한 칸씩 건너뛰어 1·3·5음을 쌓고, 반음 간격을 관찰해 장·단·감 화음의 정체를 밝혀** 무너진 화성 탑을 복원한다.

# 1. 교육 목표와 범위

## 1.1 최종 학습 성과

플레이어는 게임을 완료한 뒤 다음을 할 수 있어야 한다.

1. 조표를 보고 해당 장조·단조의 7음 음계를 정확히 구성한다.
2. 각 음계도 위에서 음계 안의 음만 사용해 1·3·5음을 쌓는다.
3. 두 개의 3도 간격을 반음 수로 판정해 장3화음, 단3화음, 감3화음, 증3화음을 구별한다.
4. 장조의 `I–ii–iii–IV–V–vi–vii°` 패턴을 조성이 바뀌어도 적용한다.
5. 자연단조의 `i–ii°–III–iv–v–VI–VII` 패턴을 조성이 바뀌어도 적용한다.
6. 로마 숫자와 코드 이름을 서로 변환한다.
7. 토닉·프리도미넌트·도미넌트 기능을 기초 수준에서 구분한다.
8. 상대장조와 상대단조가 같은 조표를 공유하지만 중심음과 기능이 다름을 설명한다.
9. 코드 표기에서 음이름의 철자를 지킨다. 예: G♭ 장조의 IV는 `C♭`이지 `B`가 아니다.
10. 선택형 답만 고르는 것이 아니라 임의의 조성에서 코드를 직접 생성한다.

## 1.2 반드시 가르칠 핵심 원리

### 장조

- 음계 간격: `전–전–반–전–전–전–반`
- 3화음 품질: `장–단–단–장–장–단–감`
- 로마 숫자: `I–ii–iii–IV–V–vi–vii°`

### 자연단조

- 음계 간격: `전–반–전–전–반–전–전`
- 3화음 품질: `단–감–장–단–단–장–장`
- 로마 숫자: `i–ii°–III–iv–v–VI–VII`

### 고급 선택 콘텐츠: 화성단음계

- 자연단음계의 7음을 반음 올린다.
- 3화음 품질: `단–감–증–단–장–장–감`
- 로마 숫자: `i–ii°–III+–iv–V–VI–vii°`
- 본편 초반에는 섞지 않는다. 자연단조를 충분히 익힌 뒤 “도미넌트 복원 연구실”에서 예외로 소개한다.

## 1.3 범위 밖으로 두는 것

MVP에서는 다음을 필수 학습에 넣지 않는다.

- 7th 코드 전체 체계
- 전조 분석
- 차용화음·세컨더리 도미넌트
- 네아폴리탄·증6화음
- 재즈 보이싱
- 고정도법과 이동도법 논쟁
- 정확한 성부 진행 규칙

단, 데이터 구조와 UI는 나중에 7th 코드와 전위를 추가할 수 있도록 확장 가능하게 만든다.

# 2. 세계관과 캐릭터

## 2.1 세계관

“톤테라”는 12개의 조성 지역이 **5도권 궤도**를 따라 연결된 세계다. 각 지역에는 장조의 태양 도시와 상대단조의 달 동굴이 한 쌍으로 존재한다. 세계의 화성 중심을 지키던 “다이아토닉 코어”가 산산조각 나면서, 모든 지역의 화음 탑이 음을 잃었다.

플레이어는 견습 “코드 크래프터”가 되어 다음 과정을 반복한다.

1. 조표 문을 연다.
2. 7개의 음계 조각을 모은다.
3. 3도 계단으로 1·3·5음을 쌓는다.
4. 화음의 품질 인장을 붙인다.
5. 로마 숫자 문장을 해독한다.
6. 코드 진행을 연주해 지역의 빛을 되찾는다.

## 2.2 주요 캐릭터

### 루미
- 역할: 안내 요정
- 성격: 빠르고 명확하며 실수를 비난하지 않는다.
- 대표 대사:  
  “답을 외우지 않아도 괜찮아. 음계에서 한 칸씩 건너뛰면 화음이 보여!”

### 테르티
- 역할: 3도 쌓기 연구원
- 비주얼: 두 칸씩 점프하는 작은 로봇
- 대표 대사:  
  “루트에서 하나 건너뛰고, 또 하나 건너뛰기. 이게 1–3–5 규칙이야.”

### 센토
- 역할: 반음 측정 기사
- 비주얼: 반음 구슬을 세는 측정기
- 대표 대사:  
  “4+3이면 장, 3+4면 단, 3+3이면 감. 귀와 눈을 같이 써 보자.”

### 로마
- 역할: 도수·로마 숫자 기록관
- 대표 대사:  
  “대문자는 장화음, 소문자는 단화음, 작은 원은 감화음이야.”

### 도미나
- 역할: 보스이자 최종 조력자
- 설정: 도미넌트 힘을 과도하게 사용해 코어를 깨뜨렸으나, 후반에 해결 원리를 알려 준다.
- 대표 대사:  
  “긴장은 나쁜 것이 아니다. 어디로 해결되는지 모를 때 혼란이 생긴다.”

# 3. 게임의 핵심 루프

## 3.1 30초 단위 기본 루프

1. 화면 상단에서 오늘의 조성과 조표를 확인한다.
2. 하단 음표 덱에서 필요한 음을 탭 또는 드래그한다.
3. 중앙 음계 링이나 오선 슬롯에 7음을 배열한다.
4. 특정 도수를 선택한다.
5. 선택한 음에서 한 칸씩 건너뛰어 세 음을 화음 탑에 넣는다.
6. 완성된 화음을 블록음 또는 아르페지오로 듣는다.
7. `장 / 단 / 감 / 증` 인장을 선택한다.
8. 로마 숫자와 기능을 연결한다.
9. 즉시 피드백을 받고, 틀렸다면 원인을 단계별로 확인한다.
10. 에너지 조각·별·숙련도를 획득하고 다음 문제로 간다.

## 3.2 학습을 방해하지 않는 실패 설계

- 목숨을 소모하지 않는다.
- 첫 오답에서는 정답을 바로 보여 주지 않는다.
- 두 번째 오답에서 음계의 해당 음을 강조한다.
- 세 번째 오답에서 “한 칸 건너뛰기” 경로를 애니메이션으로 보여 준다.
- 마지막에는 정답을 자동 완성한 뒤, 플레이어가 직접 다시 한 번 재현해야 통과한다.
- 오답 메시지는 “틀렸다”보다 “어느 규칙이 어긋났는지”를 말한다.

### 피드백 문구 예시

- 잘못된 음계음 사용:  
  `이 조성에서는 F가 아니라 F♯가 열려 있어. 조표의 첫 번째 샤프를 확인해 보자.`
- 글자 철자 오류:  
  `소리는 같아도 이 화음의 3음은 B가 아니라 C♭로 적어야 1–3–5 글자 순서가 유지돼.`
- 3도 쌓기 오류:  
  `루트 다음 음을 바로 고르지 말고 음계에서 하나를 건너뛰어 줘.`
- 품질 판정 오류:  
  `아래 3도는 3반음, 위 3도는 4반음이므로 단3화음이야.`

# 4. 모바일 화면 구조

## 4.1 기준 해상도

- 기준 프레임: `390 × 844`
- 방향: 세로 고정이 기본
- 최소 대응: `320 × 568`
- 태블릿·가로 화면: 중앙 게임 보드를 최대 폭 520px로 제한하고 양쪽에 장식 또는 학습 로그 표시
- 모든 화면은 `env(safe-area-inset-*)`를 반영한다.

## 4.2 게임 플레이 화면 레이아웃

### 상단 15%
- 뒤로 가기
- 현재 조성: `G 장조`
- 조표 배지: `♯ 1개: F♯`
- 문제 진행: `3 / 7`
- 설정·음소거

### 중앙 50%
- 2D 배경
- 음계 링 또는 오선
- 코드 탑 3칸: `Root / 3rd / 5th`
- 캐릭터와 말풍선
- 반음 구슬 또는 간격 표시

### 하단 35%
- 음표 카드 덱
- 품질 인장 버튼
- 로마 숫자 버튼
- 듣기 버튼
- 힌트 버튼
- 확정 버튼

## 4.3 터치 규칙

- 최소 터치 영역: 48×48px
- 드래그뿐 아니라 탭 선택 → 슬롯 탭 배치도 제공
- 잘못 놓은 카드는 원래 자리로 스프링 애니메이션
- 진동은 선택 사항이며 설정에서 끌 수 있다.
- 길게 누르기만으로 필수 기능을 실행하지 않는다.
- 색상만으로 장·단·감 품질을 구별하지 않고 아이콘·문자·모양을 함께 사용한다.

# 5. 전체 콘텐츠 지도

## 5.1 12개 상대조 지역

| 순서 | 지역명 | 조성 쌍 | 새 학습 초점 | 지역 보스 진행 |
|---:|---|---|---|---|
| 01 | 무조표의 정원 | C 장조 ↔ A 단조 | 조표 없이 음계·3도 쌓기·장/단 패턴 이해 | C–Am–F–G / Am–F–C–G |
| 02 | 한 개의 빛나는 문 | G 장조 ↔ E 단조 | F♯를 조표로 읽고 모든 F를 자동 변환 | G–D–Em–C / Em–C–G–D |
| 03 | 한 개의 그림자 문 | F 장조 ↔ D 단조 | B♭를 조표로 읽고 임시표와 구별 | F–C–Dm–B♭ / Dm–B♭–F–C |
| 04 | 두 개의 톱니섬 | D 장조 ↔ B 단조 | F♯·C♯, 으뜸음이 바뀌어도 동일한 화음 품질 패턴 전이 | D–A–Bm–G / Bm–G–D–A |
| 05 | 두 개의 안개섬 | B♭ 장조 ↔ G 단조 | B♭·E♭, 플랫 표기와 코드 철자 유지 | B♭–F–Gm–E♭ / Gm–E♭–B♭–F |
| 06 | 세 개의 번개탑 | A 장조 ↔ F♯ 단조 | 3개 샤프를 빠르게 적용하고 상대조 비교 | A–E–F♯m–D / F♯m–D–A–E |
| 07 | 세 개의 수정동굴 | E♭ 장조 ↔ C 단조 | 3개 플랫, 장조와 단조의 동일 조표·다른 중심음 | E♭–B♭–Cm–A♭ / Cm–A♭–E♭–B♭ |
| 08 | 네 개의 전류도시 | E 장조 ↔ C♯ 단조 | iii·vi 및 ii°를 포함한 빠른 화음 판정 | E–B–C♯m–A / C♯m–A–E–B |
| 09 | 네 개의 구름성 | A♭ 장조 ↔ F 단조 | 플랫 조성에서 음이름 글자 순서를 보존 | A♭–E♭–Fm–D♭ / Fm–D♭–A♭–E♭ |
| 10 | 다섯 개의 태양관문 | B 장조 ↔ G♯ 단조 | A♯까지 포함한 복합 샤프 조표·청음 전이 | B–F♯–G♯m–E / G♯m–E–B–F♯ |
| 11 | 다섯 개의 달관문 | D♭ 장조 ↔ B♭ 단조 | C♭가 없는 5플랫 조성의 정확한 철자와 기능 | D♭–A♭–B♭m–G♭ / B♭m–G♭–D♭–A♭ |
| 12 | 여섯 개의 거울왕국 | G♭ 장조 ↔ E♭ 단조 | C♭를 포함한 6플랫 조성과 종합 전이 | G♭–D♭–E♭m–C♭ / E♭m–C♭–G♭–D♭ |

## 5.2 각 조성의 공통 6단계

모든 장조와 단조는 같은 구조를 사용하되, 음계·조표·코드·배경·보스 진행만 데이터로 바뀐다.

1. **조표 문 열기**  
   조표를 적용해 7음 음계를 완성한다.
2. **3도 계단 오르기**  
   특정 도수에서 1·3·5음을 쌓는다.
3. **화음 품질 감정소**  
   장·단·감·증을 간격으로 판정한다.
4. **로마 숫자 도서관**  
   코드 이름과 도수를 연결한다.
5. **기능 다리 복원**  
   토닉·프리도미넌트·도미넌트 기초 기능을 분류한다.
6. **진행 코어 보스전**  
   4개의 코드를 올바른 순서로 배열하고 연주한다.

각 상대조 지역은 장조 6단계 + 단조 6단계 + 비교 보스 1단계로 구성한다.

- `12개 지역 × 13개 스테이지 = 156개 스테이지`
- 스테이지를 156개 수작업으로 만들지 않는다.
- `KeyDefinition + LevelTemplate + SeededQuestionGenerator`로 생성한다.

# 6. 조성별 이론 데이터

## 6.1 12개 장조

장조의 화음 품질 순서는 모든 조에서 동일하다.

`I 장 / ii 단 / iii 단 / IV 장 / V 장 / vi 단 / vii° 감`

| # | 조성 | 조표 | 음계 | 다이아토닉 3화음 | 대표 진행 |

# 7. 스테이지 템플릿 상세

## 7.1 스테이지 1: 조표 문 열기

### 목적
조표를 단순 암기하지 않고, 모든 해당 음이 일관되게 변한다는 것을 이해한다.

### 시작 화면
- 문 위에 조표가 표시된다.
- 예: G 장조라면 `♯ 1개`
- 음표 카드 10장: 정답 7장 + 오답 3장
- 오답 카드 예: `F`, `B♭`, `C♯`

### 플레이 순서
1. 루미가 으뜸음 카드를 자동으로 첫 슬롯에 놓는다.
2. 플레이어가 글자 순서대로 나머지 6음을 놓는다.
3. 모든 음을 놓으면 음계가 오름차순으로 재생된다.
4. 조표와 충돌하는 음이 있으면 해당 카드와 조표가 동시에 깜박인다.
5. 완성 후 “전·전·반·전·전·전·반” 발판이 나타난다.
6. 플레이어가 반음 위치 두 곳을 탭해 확인한다.
7. 통과 시 “음계 코어” 획득.

### 오답 처리
- F를 놓은 경우: `G 장조의 조표는 모든 F를 F♯로 바꿔.`
- A♯를 놓은 경우: `글자 순서는 맞지만 조표에 없는 임시표야.`

### 통과 조건
- 7개 음 정확히 배치
- 반음 위치 2곳 정확히 선택
- 자동 정답 표시 후에는 동일 문제를 힌트 없이 한 번 재현

## 7.2 스테이지 2: 3도 계단 오르기

### 목적
코드 구성음을 외우기보다 음계에서 한 칸씩 건너뛰는 규칙을 체화한다.

### 플레이 순서
1. 7음이 원형으로 배치된다.
2. 문제에 `4도 위에 화음 탑을 세워라`가 표시된다.
3. 4도 음이 루트 슬롯에 자동 강조된다.
4. 플레이어가 음계에서 하나 건너뛴 음을 3음 슬롯에 놓는다.
5. 다시 하나 건너뛴 음을 5음 슬롯에 놓는다.
6. 원형 끝을 넘어가면 처음으로 순환한다.
7. 완성된 세 음을 블록음과 아르페지오로 각각 듣는다.
8. 간격 측정 단계로 넘어간다.

### 예시: C 장조 4도
- 루트: F
- 하나 건너뜀: A
- 또 하나 건너뜀: C
- 결과: F–A–C

### 핵심 시각화
- 선택한 루트에서 `+2 scale steps`, 다시 `+2 scale steps`
- 반음 수가 아니라 **음계도 기준으로 먼저** 쌓는다.
- 품질 판정 단계에서만 반음 수를 센다.

## 7.3 스테이지 3: 화음 품질 감정소

### 목적
장·단·감 화음을 음 이름 암기 없이 간격으로 판정한다.

### 판정 규칙
- 장3화음: `4 + 3`
- 단3화음: `3 + 4`
- 감3화음: `3 + 3`
- 증3화음: `4 + 4`

### 플레이 순서
1. 완성된 3화음의 아래 3도와 위 3도 사이에 반음 구슬이 나타난다.
2. 플레이어가 피아노 건반 미니뷰에서 반음을 센다.
3. `장 / 단 / 감 / 증` 인장 중 하나를 코드 탑에 끌어놓는다.
4. 정답이면 인장이 빛나고 코드 기호가 나타난다.
5. 오답이면 두 간격 중 어느 쪽을 잘못 셌는지 보여 준다.

### 교육 문구
- `C–E는 4반음, E–G는 3반음 → 장3화음`
- `D–F는 3반음, F–A는 4반음 → 단3화음`
- `B–D는 3반음, D–F는 3반음 → 감3화음`

## 7.4 스테이지 4: 로마 숫자 도서관

### 목적
도수와 코드 품질을 하나의 표기로 읽는다.

### 플레이 순서
1. 코드 이름 3개와 로마 숫자 5개를 보여 준다.
2. 플레이어가 코드 이름을 해당 로마 숫자에 연결한다.
3. 대문자·소문자·감화음 원의 의미를 확인한다.
4. 두 번째 라운드에서는 로마 숫자만 보고 코드를 직접 만든다.
5. 세 번째 라운드에서는 코드를 듣고 후보 중 로마 숫자를 고른다.

### 예시: G 장조
- G → I
- Am → ii
- Bm → iii
- C → IV
- D → V
- Em → vi
- F♯dim → vii°

## 7.5 스테이지 5: 기능 다리 복원

### 목적
각 코드가 진행 안에서 가지는 기초 역할을 체감한다.

### 비유
- 토닉: 집
- 프리도미넌트: 출발·이동
- 도미넌트: 긴장·귀환 요청

### 플레이 순서
1. 세 개의 섬이 나타난다: 집, 길, 문.
2. 코드 카드를 적절한 섬으로 이동한다.
3. 분류가 끝나면 예시 진행을 연주한다.
4. 도미넌트 뒤에 토닉을 놓으면 문이 열리고 해소 애니메이션이 나온다.
5. 같은 코드를 다른 문맥에 쓸 수 있음을 짧게 안내하되, 입문 기본 분류를 우선한다.

## 7.6 스테이지 6: 진행 코어 보스전

### 목적
음계–코드–기능–소리를 하나의 과제로 통합한다.

### 보스전 구조
1. 조표 확인
2. 4개 로마 숫자 공개
3. 각 로마 숫자의 코드 구성
4. 코드 품질 검증
5. 올바른 순서로 타임라인에 배치
6. 리듬 패턴 선택
7. 전체 진행 연주
8. 마지막 코드가 토닉으로 해결되는지 판단

### 보스 체력
- 이론 정확도 50%
- 코드 구성 정확도 30%
- 기능·해결 선택 20%
- 시간은 학습 모드에서 점수에 반영하지 않는다.

### 승리 연출
- 지역 배경의 색이 돌아온다.
- 완성한 진행을 2마디 루프로 재생한다.
- 플레이어 이름이 “복원자 기록판”에 표시된다.
- 해당 조성의 자유 연습 모드가 열린다.

3. 테르티:
   - `바로 옆 D는 지나가고 E를 골라.`
4. 플레이어가 E를 놓는다.
5. 다시 F를 건너뛰고 G를 놓는다.
6. C–E–G가 블록음으로 울린다.
7. 반음 구슬로 4+3을 확인한다.
8. `장` 인장을 붙인다.
9. `C 장화음 = I` 카드가 도감에 저장된다.

## 8.4 튜토리얼 9:00–13:00 — ii와 vii° 비교

1. D 위에 D–F–A를 만든다.
2. 3+4를 확인하고 단화음 인장을 붙인다.
3. B 위에 B–D–F를 만든다.
4. 3+3을 확인하고 감화음 인장을 붙인다.
5. 센토:
   - `같은 음계 재료를 써도 출발점에 따라 간격이 달라져.`
6. 세 화음 C, Dm, Bdim을 차례로 듣는다.
7. 플레이어가 들리는 안정감 순서를 직관적으로 선택한다.
8. 정답 여부보다 청감 기록을 남기고 해설을 제공한다.

## 8.5 튜토리얼 13:00–17:00 — 7개 화음 완성

1. 일곱 개의 비어 있는 탑이 등장한다.
2. I, IV, V는 가이드가 일부 제공된다.
3. ii, iii, vi는 플레이어가 완성한다.
4. vii°는 직전 학습을 복습한다.
5. 완성 후 패턴이 화면에 나타난다:
   - `장–단–단–장–장–단–감`
6. 플레이어가 패턴을 세 그룹으로 묶는다:
   - 장: I, IV, V
   - 단: ii, iii, vi
   - 감: vii°
7. 패턴 카드를 획득한다.

## 8.6 튜토리얼 17:00–20:00 — 첫 진행 보스

1. 보스가 `I–vi–IV–V` 룬을 섞는다.
2. 플레이어가 C, Am, F, G를 각각 만든다.
3. 타임라인에 올바른 순서로 배치한다.
4. 코드 진행을 80 BPM으로 재생한다.
5. 마지막 V 뒤에 I을 한 번 더 놓아 해소시킨다.
6. C 장조 지역이 복원된다.
7. A 단조 달 동굴이 열리며 다음 대사가 나온다:
   - `같은 음들을 쓰는데도 중심이 A로 바뀌면 분위기와 역할이 달라져.`

# 9. 상대장조·단조 비교 스테이지

## 9.1 핵심 과제

예: C 장조와 A 단조

1. 두 음계를 나란히 놓는다.
2. 사용 음이 동일함을 확인한다.
3. 시작점과 귀결점이 다름을 듣는다.
4. C–E–G와 A–C–E를 비교한다.
5. 장조 품질 패턴과 자연단조 품질 패턴을 나란히 본다.
6. 같은 코드가 서로 다른 도수·기능을 가질 수 있음을 연결한다.
   - C 장조의 C = I
   - A 단조의 C = III
7. 짧은 멜로디를 듣고 어느 중심으로 느껴지는지 선택한다.
8. 마지막 음과 반복되는 베이스를 단서로 설명한다.

## 9.2 비교 보스 예시

- 왼쪽 코어: `C–Am–F–G`
- 오른쪽 코어: `Am–F–C–G`
- 플레이어는 동일한 네 코드가 서로 다른 중심감을 만드는 이유를 다음 카드로 조립한다.
  - `시작 코드`
  - `마지막 해결`
  - `베이스 반복`
  - `강박의 코드`
- 게임은 하나의 단서만으로 조성을 단정하지 않고 전체 맥락을 본다는 해설을 제공한다.

# 16. 음악이론 데이터 모델

## 16.1 핵심 타입 예시

```ts
type Letter = 'C' | 'D' | 'E' | 'F' | 'G' | 'A' | 'B';
type Accidental = 'bb' | 'b' | 'natural' | '#' | '##';
type Mode = 'major' | 'naturalMinor' | 'harmonicMinor';
type ChordQuality = 'major' | 'minor' | 'diminished' | 'augmented';
type HarmonicFunction = 'tonic' | 'predominant' | 'dominant';

interface SpelledNote {
  letter: Letter;
  accidental: Accidental;
  midiClass: number;
  display: string;
}

interface KeyDefinition {
  id: string;
  tonic: SpelledNote;
  mode: Mode;
  koreanName: string;
  keySignature: Partial<Record<Letter, Accidental>>;
  scale: SpelledNote[];
  relativeKeyId?: string;
  enharmonicAliasIds?: string[];
}

interface DiatonicTriad {
  degree: 1 | 2 | 3 | 4 | 5 | 6 | 7;
  notes: [SpelledNote, SpelledNote, SpelledNote];
  quality: ChordQuality;
  romanNumeral: string;
  symbol: string;
  function: HarmonicFunction;
}

interface LevelDefinition {
  id: string;
  keyId: string;
  templateId: string;
  difficulty: number;
  seed: string;
  learningObjectives: string[];
}
```

## 16.2 음 철자 규칙

피치 클래스만 계산해서 임의로 가장 짧은 이름을 고르면 안 된다.

예: G♭ 장조의 IV
- 루트 글자: C
- 3음 글자: E
- 5음 글자: G
- 조표 적용 결과: C♭–E♭–G♭
- 이를 B–D♯–F♯로 바꾸면 소리는 같아도 해당 조성의 다이아토닉 철자가 아니다.

### 구현 순서

1. 으뜸음의 글자부터 A–G 순서를 7개 생성한다.
2. 장·단 음계의 목표 반음 패턴을 계산한다.
3. 각 글자에 필요한 임시표를 붙여 목표 피치 클래스와 일치시킨다.
4. 코드 구성은 음계 배열에서 `[degree, degree+2, degree+4] mod 7`로 선택한다.
5. 품질은 철자와 별개로 실제 반음 간격을 계산해 판정한다.
6. 표시 문자열과 내부 피치 클래스를 분리한다.

## 16.3 필수 도메인 함수

```ts
buildScale(key: KeyDefinition): SpelledNote[]
buildDiatonicTriad(key: KeyDefinition, degree: 1|2|3|4|5|6|7): DiatonicTriad
buildAllDiatonicTriads(key: KeyDefinition): DiatonicTriad[]
identifyTriadQuality(notes: SpelledNote[]): ChordQuality
getRomanNumeral(mode: Mode, degree: number, quality: ChordQuality): string
getHarmonicFunction(mode: Mode, degree: number): HarmonicFunction
transposeProgression(romanNumerals: string[], key: KeyDefinition): DiatonicTriad[]
validateSpelling(notes: SpelledNote[], key: KeyDefinition): ValidationResult
```

## 음악이론 규칙

### 장조
- 음계 패턴: 전–전–반–전–전–전–반
- 품질: 장–단–단–장–장–단–감
- 로마 숫자: I–ii–iii–IV–V–vi–vii°

### 자연단조
- 음계 패턴: 전–반–전–전–반–전–전
- 품질: 단–감–장–단–단–장–장
- 로마 숫자: i–ii°–III–iv–v–VI–VII

### 화성단음계
- 본편 초반과 섞지 말고 고급 선택 모드로 둔다.
- 자연단음계의 7음만 반음 올린다.
- 품질: 단–감–증–단–장–장–감
- 로마 숫자: i–ii°–III+–iv–V–VI–vii°

### 기능 기본값
장조:
- tonic: I, iii, vi
- predominant: ii, IV
- dominant: V, vii°

자연단조:
- tonic: i, III, VI
- predominant: ii°, iv
- dominant 계열: v, VII

자연단조 v를 자동으로 V로 바꾸지 마라.

## 철자 규칙

피치 클래스만 보고 가장 흔한 이명동음으로 치환하지 마라.
음이름 글자 순서를 먼저 만든 뒤 임시표를 계산하라.

예:
- G♭ 장조 음계: G♭ A♭ B♭ C♭ D♭ E♭ F
- G♭ 장조 IV: C♭ E♭ G♭
- 이를 B D♯ F♯로 표시하면 오답이다.

구현 알고리즘:

1. 으뜸음에서 시작해 A–G 글자를 순서대로 7개 만든다.
2. 모드의 반음 패턴에 맞도록 각 글자의 임시표를 계산한다.
3. degree d의 3화음은 scale[d], scale[d+2], scale[d+4]를 modulo 7로 선택한다.
4. 실제 반음 간격으로 품질을 판정한다.
5. 표시 철자와 내부 pitch class를 분리한다.
6. bb, b, natural, #, ##를 지원한다.
7. 유니코드 𝄪가 표시되지 않으면 ## 폴백을 사용한다.

# 25. 개발자가 자주 틀리는 지점

1. **장조 패턴을 데이터로 넣었는데 코드 철자가 깨짐**  
   원인: pitch class에서 가장 짧은 음이름을 선택함.  
   해결: 글자 순서를 먼저 만들고 임시표를 계산한다.

2. **자연단조의 V를 장화음으로 생성함**  
   원인: 기능화성 관습을 자연단음계 데이터에 섞음.  
   해결: 자연단조는 v 단화음, 화성단음계에서만 V 장화음.

3. **화면은 게임처럼 보이지만 선택형 퀴즈뿐임**  
   해결: 반드시 음계 배열 → 1·3·5 구축 → 간격 판정의 조작을 넣는다.

4. **드래그가 모바일에서 스크롤과 충돌함**  
   해결: 게임 영역의 포인터 처리, 적절한 `touch-action`, 탭 대체를 구현한다.

5. **오디오가 iOS에서 재생되지 않음**  
   해결: 첫 명시적 사용자 탭에서 AudioContext를 생성·resume한다.

6. **156개 레벨을 JSON으로 복붙함**  
   해결: 공통 템플릿과 keyId, 난이도, seed만 저장한다.

7. **감화음을 실패·악당 이미지로만 표현함**  
   해결: 긴장과 연결 역할로 설명하고 부정적 가치 판단을 피한다.

8. **색으로만 장·단을 구별함**  
   해결: M/m/°/+, 도형, 텍스트, 아이콘을 함께 쓴다.

# 27. 최종 구현 원칙 요약

1. 정답 암기보다 생성 원리를 먼저 보여 준다.
2. 음계도 기반 1·3·5 쌓기와 반음 기반 품질 판정을 구분한다.
3. 조성이 바뀌어도 패턴이 전이된다는 경험을 반복한다.
4. 소리가 같아도 이론적 철자가 다를 수 있음을 존중한다.
5. 자연단조와 화성단음계를 명확히 분리한다.
6. 학습 모드에서 시간과 목숨으로 압박하지 않는다.
7. 드래그 외 탭 대체를 제공한다.
8. 음악이론 엔진은 순수 함수와 테스트로 보호한다.
9. 콘텐츠는 데이터와 템플릿으로 확장한다.
10. 플레이어가 완성한 코드는 반드시 들려 준다.
