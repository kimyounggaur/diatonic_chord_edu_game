# 구현 기록

## 그림 롤북

상단의 게임 롤북 버튼은 플레이 중에도 현재 문제와 답을 유지한 채 가이드를 엽니다. 11개 장에 34개의 설명 도식과 표지 삽화를 배치했습니다. 장별 탐색, 모바일 목차, Esc 닫기, 키보드 포커스 이동과 화면 읽기 도구를 지원합니다. 예시는 실제 게임의 자연단조·점수·복습·해금 규칙에 맞춥니다.

## 2026-11-16 복습·재생 보완

- 홈에서 복습 목록으로 이동하고, 기록된 조성·스테이지·문항을 한 문제씩 다시 풀 수 있습니다. 복습은 캠페인 완료·별·해금을 변경하지 않습니다.
- 새 오답은 문항을 구분해 저장합니다. 힌트 없이 첫 시도에 맞힌 해당 문항만 복습 연속 정답이 올라가며, 세 번 성공하면 목록에서 제거됩니다. 이전 저장에는 문항 ID가 없어 개념 단위로 복습합니다.
- 같은 유형의 다른 도수가 있는 과제는 오답을 기록한 세션 말미에 다른 도수로 복습합니다. 음계와 상대조 등 다른 도수 변형이 없는 과제의 세션 말미 변형은 아직 제공하지 않습니다. 세 문항 연속 독립 정답 시 자동 설명을 줄이고 일부 선택지의 수를 늘립니다.
- 기능 학습의 해결 청음은 V→I를, 보스의 해결 청음은 실제 진행 마지막 화음→I를 재생합니다. 자유 연습에서 조성의 음계 모드를 바꾸면 조표도 함께 바뀌며 화성단음계의 올린 7음은 조표에 넣지 않습니다.
- 기존 Playwright 러너는 이 실행 환경에서 Chromium 소켓 권한 제한으로 시작 전 차단되었습니다. 실제 iOS·Android 기기와 오프라인 설치 동작도 별도 확인이 필요합니다.

기준일: 2026-11-16. 이 문서는 원본 설계서와 구분하여 현재 소스에서 구현한 동작과 검증의 한계를 기록합니다.

## 구조와 책임

React 19·TypeScript·Vite 앱입니다. React DOM이 화면 전환과 조작 가능한 학습 UI를 담당하고, Phaser 3는 홈의 2D 왕국 장면을 그립니다. 카드와 슬롯의 실질적인 학습 조작은 키보드·스크린리더·탭 대체 조작을 제공하기 위해 DOM 버튼과 Pointer Events로 구현했습니다. Phaser 캔버스만으로 조작을 제공하지 않습니다.

Zustand가 설정과 완료 진행을 보관합니다. 화면 이동은 해시 경로로 제공하며 서버 라우팅이나 앱 전용 백엔드는 없습니다. `src/domain`의 음악이론·학습 로직은 React와 Phaser를 가져오지 않는 순수 TypeScript 모듈입니다.

## 음악이론 범위

핵심 상대조 쌍은 C/A, G/E, F/D, D/B, B♭/G, A/F♯, E♭/C, E/C♯, A♭/F, B/G♯, D♭/B♭, G♭/E♭입니다. 각 쌍에서 첫 표기는 장조, 두 번째는 자연단조입니다. 고급 거울은 F♯/D♯, C♯/A♯, C♭/A♭입니다. 총 장조 15개와 자연단조 15개를 표기별로 보관합니다.

`worlds.ts`가 각 지역에 장조 6개, 자연단조 6개, 비교 1개를 생성하므로 핵심 156개, 확장 포함 195개입니다. 단계별 실제 문항 수는 과제에 따라 다릅니다. 음계 단계는 배열과 반음 확인, 쌓기·품질은 7도수, 로마 숫자는 연결·구축·시각 대체 청음, 기능은 분류와 해결, 보스는 4화음 구축·품질·배열·재생·해결, 상대조는 공통 음·도수 변화·문맥 비교를 다룹니다.

화음의 1·3·5는 음계에서 두 칸씩 건너뛰어 선택하고 품질은 실제 반음 간격으로 판정합니다. 표기와 피치 클래스를 분리하여 G♭ 장조 IV를 C♭–E♭–G♭로 유지합니다. E♯, B♯, F♭, C♭, 겹임시표를 지원합니다. 화성단음계는 자유 연습에서 자연단음계와 별도로 선택하며 캠페인 데이터에는 섞지 않습니다.

기능은 설계서의 입문 분류를 사용합니다. 장조와 자연단조 모두 1·3·6은 토닉, 2·4는 프리도미넌트, 5·7은 도미넌트 계열로 다룹니다. 실제 곡의 모든 문맥을 분석하는 화성 분석 엔진은 아닙니다. 자연단조 v는 단화음으로 보존합니다.

## 진행과 조작

C 장조 6단계를 순서대로 완료하면 A 자연단조가 열립니다. 지역의 장·단조 12단계를 마친 뒤 비교 보스를 완료하면 다음 지역으로 이동합니다. 홈의 이어하기, 지도 진입, 다음 임무 진입에서 선행 단계와 고급 지역 표시 설정을 확인합니다. 고급 지역 표시를 꺼도 이미 저장된 기록은 유지합니다. 도감과 자유 연습에서는 조성을 자유롭게 선택할 수 있습니다.

카드 탭은 다음 빈칸을 채우며 슬롯을 눌러 바꾸거나 포인터로 직접 끌어놓을 수 있습니다. 루트와 음계 첫 음은 가이드로 미리 제공합니다. 장·단·감·증은 문자와 기호를 함께 표시합니다. 첫 오답은 규칙을 설명하고, 두 번째는 관련 음을 강조하며, 세 번째 오답에서는 완성 경로를 제시합니다. 자동 제시만으로 완료 처리하지 않고 답을 지운 후 직접 재현해야 합니다.

문항 점수는 첫 시도 100, 두 번째 70, 세 번째 40, 안내 후 재현 20이며 힌트마다 15점을 차감하고 0점 아래로 내려가지 않습니다. 듣기와 학습 시간에는 감점이 없습니다. 완료는 별 1개, 평균 75 이상은 2개, 평균 90 이상이며 자동완성 없이 완료하면 3개입니다. 재도전 시 최고 별을 유지합니다. 개념별 숙련도는 `round(old * 0.8 + score * 0.2)`로 갱신하며, 어려웠던 문항은 복습 큐에 기록합니다.

## 도전 6종

C 장조 진행 보스 완료 후 공통으로 열립니다. 도전은 캠페인 스테이지와 별개이며 현재 세션에서 첫 시도 정답 수·풀이 수·정확도를 표시합니다. 영구 최고 기록·순위·도전 별·해금 보상은 저장하지 않습니다.

| 모드 | 과제 | 세션 범위 |
|---|---|---|
| 60초 조표 질주 | 장·단조 조건과 조표를 보고 조성을 선택 | 최대 60초, 30문항 |
| 7개 화음 연속 구축 | C 장조 1~7도의 루트·3음·5음을 직접 구성 | 시간제한 없이 7개 |
| 로마 숫자 변환 | 조성 안의 코드 이름을 정확한 로마 숫자로 변환 | 최대 60초, 20문항 |
| 철자 오류 탐지 | 조표와 1·3·5 글자 순서를 지킨 표기 선택 | 시간제한 없이 10문항 |
| 코드 품질 청음 | 합성 화음의 장·단·감 품질 판정 | 시간제한 없이 14문항, 구성음·간격 시각 대체 |
| 5도권 릴레이 | 다음 완전5도 음고 중심의 장조 선택 | 시간제한 없이 12문항 |

도전 문제는 시드로 생성하며 한 세션의 풀에서 같은 문제를 반복하지 않습니다. 구축 도전은 틀린 화음을 직접 다시 쌓아야 다음으로 이동하며, 재시도 성공이 첫 시도 정답 수를 소급해서 늘리지 않습니다. 철자 도전은 G♭ 장조 IV의 C♭–E♭–G♭를 먼저 다루고, 5도권의 F♯→D♭ 연결에는 C♯/D♭ 이명동음 설명을 제공합니다.

## 저장과 오디오

브라우저 저장 키는 `chord-crafter-save`, 스키마 버전은 1입니다. 완료 단계·별·해금 조성·도감·개념 숙련도·복습 큐·음색 보상 식별자·마지막 활동·설정을 저장합니다. JSON 가져오기는 알려진 조성·단계, 값 범위, 배열 크기, 날짜, 스키마를 검증한 뒤 반영합니다. 저장 실패 시 경고를 보여 주며 게임을 막지 않습니다. 진행 중인 문항의 답과 위치는 세션 상태이므로 새로고침 시 해당 스테이지를 처음부터 시작합니다.

연주는 Web Audio 발진기의 배음 합성과 엔벌로프로 만듭니다. 단음·블록·아르페지오·진행, 음량·효과음 음량·음소거·4가지 합성 음색을 제공합니다. 사용자 동작 뒤 오디오 컨텍스트를 열며 백그라운드 진입 시 재생을 중단합니다. 자유 연습 반복은 화음 시작 사이를 4박으로 맞추며 모드·도수·템포·연주 방식·오디오 설정 변경과 화면 이탈 시 중단합니다.

실제 악기 소리 인식, 마이크 접근, MIDI 입력, 녹음, 클라우드 계정·동기화, 교사용 학급 관리 기능은 없습니다. 배포 플랫폼의 로그인·비공개 접근 제어는 앱 자체 계정과 별개입니다.

## PWA 범위

`manifest.webmanifest`와 SVG 아이콘을 제공하고 프로덕션의 load 이벤트에서 서비스워커를 등록합니다. 서비스워커는 같은 출처의 실제 요청된 자산과 식별 표식이 있는 앱 HTML만 런타임 캐시에 보관합니다. 인증·API 경로, 인증 헤더가 있는 요청, 리디렉션은 캐시하지 않습니다.

처음에는 온라인 접속이 필요합니다. 서비스워커가 설치되고 제어한 이후 온라인으로 방문해 캐시된 앱 페이지와 정적 파일만 오프라인에서 재사용합니다. 설치 후 새로고침하고 필요한 화면을 온라인으로 한 번 여는 것이 필요할 수 있습니다. 모든 파일을 최초부터 미리 캐시하거나 배포 플랫폼 인증 페이지를 오프라인으로 복제하지 않습니다. 개발 서버에는 서비스워커를 등록하지 않습니다. PWA 설치 UI와 오디오 정책은 브라우저별 차이가 있으며 실물 모바일 검증은 남아 있습니다.

## 검증

기본 명령은 `npm ci`, `npm run dev`, `npm run build`, `npm test`, `npm run test:coverage`, `npm run test:e2e`입니다. E2E는 별도 실행된 앱과 Playwright에 대응하는 설치된 Chromium 실행 파일이 필요합니다. 기본 주소는 `http://127.0.0.1:5173`이고 외부 주소는 `PLAYWRIGHT_BASE_URL`로 지정합니다. 설치된 Chromium 경로는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`로 지정할 수 있고, Linux의 `/usr/bin/chromium`이 있으면 자동으로 선택합니다. 자세한 실행 예는 README에 있습니다.
